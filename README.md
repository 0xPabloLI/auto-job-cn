# auto-job-cn

中国求职自动化投简历流水线（当前支持目标站点，后续扩展某聘/某联等）：实时浏览岗位 → 筛选 → AI 起草个性化招呼语 → 自动投递 → 回复率追踪与复盘。

## 上手：三步，全程在 Agent 里对话，不用跑任何脚本

> 前提：一个 Agent 会话，其余环境 agent 会替你装好。

1. **初始化**：对 agent 说「**初始化**」（或 Setup / Onboarding / 帮我配置）。
   还没克隆仓库？先发这句：「帮我克隆 https://github.com/0xPabloLI/auto-job-cn
   并按它 docs/agents/onboarding.md 引导我初始化」，agent 装好仓库会接着引导。
   它问什么你答什么：简历（格式随意）→ 作品材料（GitHub / 网站 / 设计稿 / 文档都行）→
   想投的行业（它去调研招聘背景）→ 别投哪些公司 → 浏览器登录（也可以留到第一次投递）。
   **虽然有反风控策略，也建议用单独的小号**：老账号的历史行为跟这套拟人节奏对不上，更容易触发风控。
   完成标志：agent 告诉你 Profile 就绪（它跑过 `scripts/onboarding_check.py` 盘点全过，
   代码核验，不靠它自评）。
2. **投递**：对 agent 说「**投简历**」（「实时投简历」也行，可带时长，如「投简历，跑 1 小时」）。
   agent 实时浏览岗位、起草招呼语、逐条发送；这句话本身就是本次投递的授权。
3. **复盘**：投完后对 agent 说「**看看投递回复情况**」。agent 统计回复率、分类 HR
   反馈、回写记忆——下一轮起草自动参考「什么写法有回复」。

> **issue 策略**：本仓不开 public issue（票面与评论极易夹带个人数据）。要跟踪自己的任务就写在
> `private/notes/`（不入库）；安全与缺陷报告走 `SECURITY.md` 的私下渠道。熔断自动开票默认指向
> `origin`，若你有自己的私有 tracker，设 `AUTOJOB_ISSUE_REPO=<owner>/<repo>` 即可。
>
初始化流程的完整定义见 `docs/agents/onboarding.md`，投递执行细节见 `docs/agents/apply-runbook.md`（两份都是给 agent 读的执行文档，人不用读）。

## 默认投递节奏（全部带随机抖动，不是固定值）

- **节奏**：连投 2-4 个岗位 → 短歇 1-2.5 分钟 → 长歇 8-25 分钟再开新会话；
  间隔随时段浮动（工作时间最快，午休与夜间放慢约 1.5-2 倍）。
  **跑一小时通常 6-10 封**（纯节奏模拟期望 8-10，叠加浏览与起草耗时后实际略低；
  单次随机波动常见 5-12，偶尔 4-15）——刻意不追量、不固定间隔
- **发送前机械核验**：每条草稿发出前脚本强制过四道 gate（AI 痕迹/内部标记/白名单外事实/
  事实来源备注），违规草稿拦截不发送——不依赖 agent 自觉；称呼规范另打软提醒不拦截
- **日上限**：自动阶梯——首日 20 封，之后每天随机 +2-5 爬升、40 封封顶，实际发送量再叠加
  随机抖动；想固定上限对 agent 说一声即可
- **静默时段**：默认凌晨 0-7 点自动暂停
- **熔断**：检测到验证码/安全验证立即停下存证，等人工处置，当日不重启

## 常用指令（对 agent 说即可）

| 你说 | agent 做 |
| --- | --- |
| 「初始化」/「帮我配置」 | 引导建 Profile：简历、作品材料、行业归类与背景调研、排除公司、skills 校验、浏览器登录 |
| 「投简历」 | 实时浏览投递，起草并发送（这句话 = 本次投递授权） |
| 「看看投递回复情况」 | 回复率统计 + HR 回复分类标注 + 记忆回写 |
| 「加个 XX 行业的 Profile」 | 行业归类 + 背景调研 + 独立 Profile 并存，投递搜索词跟随行业 |
| 「XX 公司别投了」 | 写进排除公司清单，之后命中即跳过 |
| 「投递日上限改成 30」「凌晨别投」 | 调投递节奏规则，下轮投递生效 |
| 「招呼语别提 XX」/「XX 不要写了」 | 改知识库禁写约束，下一轮起草生效 |

## 个人数据与规则：在哪、怎么改

个人数据全在 `private/`（已被 `.gitignore` 排除，不进 git）：

| 位置 | 内容 |
| --- | --- |
| `private/resume.*` | 简历原文（格式不限，原样保存） |
| `private/profile_background.md` + `private/kb/` | 知识库/Profile——招呼语只能引用这里确认过的事实 |
| `private/data/excluded_companies.json` | 排除公司关键词清单（老东家/自家公司） |
| `private/data/` | 投递台账、草稿、回复记录等过程数据 |
| `private/.camoufox_profile/` | 浏览器登录态 |
| `private/profiles.json` | 多 Profile 注册表（多份简历/账号时用；单 Profile 不需要管它，#28） |

「台账」指 `private/data/applied_history.json`：投递流水账（何时投了哪家的哪个岗），全链路靠它去重防重复投递。

排查/分析用机读日志（默认关，终端提示语不受影响）：`AUTOJOB_STRUCTURED_LOG=1` 后投递/统计事件以 JSONL 落 `private/data/app.log`（多 Profile 为 `app.<名字>.log`）；凭证类信息（手机号/邮箱/token 等）自动掩码，公司名/岗位名保留便于排障。

行为规则（日上限、静默时段、限速节奏、称呼规范、搜索词）由代码与 `docs/agents/apply-runbook.md` 定义。
**不需要自己读代码改配置**——对 agent 说想要的效果（见上表），agent 会改对地方；代码只是事实来源。

## Agent 工作流全景（原理）

```
你说「初始化」                你说「投简历」                     你说「看看投递回复情况」
     │                            │                                   │
     ▼                            ▼                                   ▼
 Onboarding 引导              实时投递（live_apply）             复盘（followup）
  ├ 简历 + 作品材料            ├ 点卡片进详情看 JD                ├ 统计回复率
  ├ 个人层（锚点/硬事实/禁写）  ├ agent 实时起草                  ├ agent 分类标注 HR 回复
  ├ 行业归类 + 背景调研→行业层  ├ 脚本发送前强制四道 gate         ├ learn 回写记忆
  ├ 事实卡片 + 白名单（gate 表）├ 粘贴/逐字发送 + 动作截图         │  （下一轮起草更懂你）
  ├ skills 校验 + 登录引导      ├ 节奏/日上限/静默/熔断内置        └ eval 分组回复率
  └ 每步机械核验                └ 台账去重防重复投递                （正/反例回写走人工确认）
     scripts/onboarding_check.py
     （完成与否以退出码为准）
```

三段闭环：复盘回写的记忆直接喂给下一轮起草，越投越懂你和你的行业。

## 架构

```
live_apply.py         实时投递（唯一路径）：搜索列表点卡片进详情 → agent 会话内实时起草
                      → 脚本发送前强制四道 gate（AI 痕迹/规则扫描/内部标记/来源备注，违规拦截；
                        称呼规范软提醒不拦截）
                      → 粘贴/逐字打字发送；
                      内置节流：会话式节奏 + 自动阶梯日上限 + 静默时段（默认 0-7 点）+ 熔断；
                      进程外双看门狗（起飞前自检 + 会话中途心跳，协议楔死整树止损）；
                      动作截图 shots/ 逐岗留证（取证三件套与落空现场都吃它）
    ↓ 消费同一台账 applied_history.json（去重防重复投递）
followup_tracker.py   遍历消息列表统计 HR 回复率（linkedReplied 为核心指标）
    ↓ followup_report.json → agent 分类标注（#19/#21）→ gen_greetings.py learn 回写记忆
    ↓ gen_greetings.py eval 分组回复率报告（正/反例回写走人工确认）
onboarding_check.py   初始化机械盘点：Profile 各产物逐一核验，完成与否以退出码为准
```

## 核心设计决策

- **浏览器层**：Camoufox（Firefox 分支）+ 持久化 context + 会话式节流（连投 2-4 → 长休息，间隔随时段浮动）。平台探测与适配笔记属于内部调研材料，不随本仓分发
- **走页面 UI，不碰站内接口**：只读取页面自身发起的 XHR 响应来拿结构化数据，不自行构造站内请求——鉴权与会话始终由页面本身处理，也不做验证码绕过（检测到验证码即熔断停批）
- **LLM 过滤代替关键词规则**：关键词会把"合约产品经理"（运营）、"风控合约专家"（法律）误判为智能合约岗
- **招呼语前 15 字用"年限+成果"公式**：目标站点列表预览只露前 15 字，决定打开率
- **单消息模式**：发送前先清空账号自带的默认招呼语，避免同一岗位出现两条重复消息

## 开发（改代码）

工具链版本全部固定在 `requirements*.txt`（Python ≥ 3.9）：

```bash
pip install -r requirements-dev.txt
bash scripts/install-git-hooks.sh   # 激活 .githooks：gitleaks / doc-hierarchy lint / Session-Id

python3 -m ruff check scripts/      # lint（含命名/复杂度规则）
python3 -m ruff format --check scripts/
python3 -m mypy scripts/            # 静态类型检查
python3 -m pytest                   # 全量测试；CI 另行强制并行 + 覆盖率门槛 83%
```

CI（`.github/workflows/ci.yml`）在 push/PR 时跑同一组检查，另加 vulture（死代码）与 deptry（依赖声明一致性）。
